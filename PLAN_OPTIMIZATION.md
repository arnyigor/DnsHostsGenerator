# План доработок DnsHostsGenerator / DNS-VPN

Основан на измерениях этой сессии (31.10.2026) и на том, что реально ломалось.
Принцип: сначала то, что рвёт работу; потом скорость; потом удобство.

Отметки: `[ ]` — не сделано, `[~]` — в работе, `[x]` — сделано и проверено.

## P0 — дефекты, мешающие работе

### P0-1. `[x]` Скорость DoT: переиспользование соединения, прогрев, пул со ступенчатым открытием
**Проблема.** `UpstreamDot` синхронизирован на одном TLS-сокете: при старте приложения
десятки DNS-запросов встают в очередь. Замер: холодный запрос 0.5–1.1 с, но под нагрузкой
запросы ждут друг друга.
**Что делать.** Пул из 2–4 соединений на апстрим, выдача по кругу, переподключение при обрыве.
**Проверка.** Живой тест: 20 параллельных запросов — суммарное время не растёт линейно;
на телефоне — старт ChatGPT без очереди (по логу `FORWARD`).

### P0-2. `[x]` Автоподбор адреса включается вместе с VPN
**Проблема.** Автоподбор выключен по умолчанию; адрес прокси живёт часами, поэтому
«через сутки перестало работать» — ожидаемый исход.
**Что делать.** При включении VPN включать автоподбор (с явной надписью в статусе);
сохранять выбор пользователя, если он его выключил руками.
**Проверка.** На телефоне: включить VPN → в статусе «автоподбор включён»; в логе через
3 секунды идёт проверка пресетов.

### P0-3. `[x]` Выбор адреса по времени HTTP-ответа (и скрипт замены hosts)
**Проблема.** В hosts лежит `157.22.178.170` (6.3 с на chatgpt.com) при рабочем
`37.221.93.128` (0.78 с). Chrome с включённым «Безопасным DNS» hosts игнорирует → 403.
**Что делать.** Экспорт hosts с проверенным быстрым адресом + предупреждение, если
браузер использует DoH; инструкция по замене файла (нужны права администратора).
**Проверка.** Готовый фрагмент hosts с рабочим адресом; замер curl через него.

### P0-4. `assembleRelease` роняет Gradle-демон
**Проблема.** Релизный APK не собирается; падение на этапе конфигурации/минификации
(то же падало при попытке сделать `:dnsvpn` библиотекой).
**Что делать.** Найти причину (minify/AGP), зафиксировать; при невозможности — задокументировать
обходной путь (debug-сборка).
**Проверка.** `:androidApp:assembleRelease` завершается успешно либо причина описана с логом.

---

### P0-5. `[x]` Адрес подбирается для каждого домена отдельно
**Проблема.** Требование «один адрес на все домены» не выполнялось: `cdn.auth0.com` прокси
не обслуживает (TLS обрывается), из-за чего подбор возвращал пусто и не работал вход через
`auth.openai.com`.
**Что сделано.** `ProfileChecker.resolvePerHost` и правила из карты «домен → адрес».
**Проверка.** `resolvePerHost_picksIpPerDomain`; на телефоне служба стартует с 13 правилами.

## P1 — удобство и точность

### P1-5. Карточка правил: свёрнутый список доменов
Сейчас 7 доменов моноширинным текстом всегда на экране. Сделать: адрес крупно,
«обновлено HH:MM», домены — по нажатию.

### P1-6. Статус модуля в основном приложении
Показывать: установлен ли DNS-VPN, работает ли служба, какой адрес применён.
Кнопка «Поделиться» уже есть — добавить рядом индикатор состояния.

### P1-7. Экран модуля: прогресс и тёмная тема
Классические View без индикации «идёт проверка». Добавить прогресс на время автоподбора
и нормальную тему.

### P1-8. Объяснять вердикты проверки DNS
Показывать не «адрес не обслуживает домен», а причину: регион, отказ Cloudflare, капча,
таймаут (`REGION_BLOCKED` / `CLOUDFLARE_BLOCKED` / `CHALLENGE` / `FAILED`).

### P1-9. Несколько профилей приложений
Сейчас только ChatGPT. Вынести профили в данные: ChatGPT, Claude, Gemini —
с отдельными наборами доменов.

### P1-10. Быстрое включение VPN
Плитка в шторке (`TileService`) для включения/выключения службы.
