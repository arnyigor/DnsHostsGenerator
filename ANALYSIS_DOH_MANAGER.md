## 2. Как устроено (проверено запуском)

- EXE поднимает локальный HTTP-сервер на `127.0.0.1:8765` и открывает вкладку с UI.
  Консоли нет, при закрытии вкладки процесс выгружается сам.
- API (из `_internal/ui/index.html`): `/api/state /api/add /api/remove /api/import /api/target
  /api/check /api/progress /api/best /api/apply /api/disable /api/restart /api/open /api/quit
  /api/alive` (SSE). Проверено живьём: `GET /api/state` отдал серверы, цели, системные IP
  (`142.251.15x.2`), `POST /api/check {"page":false}` отработал 5/5, `POST /api/quit` выгрузил процесс.
- Проверка: DoH-запрос (GET `?dns=`, base64url) → TLS до 443 по полученному IP → при `page:true`
  дополнительно **headless Chrome** для 5 самых быстрых с поиском капчи/заглушки/экрана входа.
- Применение: пишет в реестр `HKLM\SOFTWARE\Policies\Google\Chrome`
  `DnsOverHttpsMode = secure` и `DnsOverHttpsTemplates = https://…/dns-query` (нужен UAC).
  Кнопка «Выключить DoH» снимает политику. Системный DNS не меняется.
- В нашем прогоне политика не применялась (`chrome: {}` в состоянии), реестр не тронут.

## 3. Результаты проверки на этой машине (реальные данные инструмента)

| DoH-сервер | Статус инструмента | Детали |
|---|---|---|
| `https://dns.dagami.ru/dns-query` | **works** | DoH 82.7 мс, TLS 390.7 мс, IP `45.147.31.32`, `dns_same=false` |
| `https://eu.geohide.ru/dns-query` | **works** | DoH 256 мс, TLS 232 мс, 7 адресов, `dns_same=false` |
| `https://dns.wlrus.cfd/dns-query` | **captcha** | `302 → https://www.google.com/sorry/…`, IP `191.217.212.16` — Google режет капчей |
| `https://dns.geohide.ru:8443/dns-query` | blocked | `handshake operation timed out` |
| `https://dns.bezmezhau.com/dns-query` | blocked | `urlopen error timed out` (DoH; DoT при этом жив — см. ниже) |

Перекрёстная проверка тем же резолверам нашими средствами (DoT/UDP + TLS-валидатор):

- `dns.dagami.ru`: работает по **UDP:53, DoT:853 и DoH**; `45.147.31.32` даёт валидный сертификат
  для chatgpt.com и gemini.google.com; для open.spotify.com отдаёт настоящие Fastly-адреса.
- `eu.geohide.ru`: 0.5–0.8 с, валидные `5.175.161.3`, `143.20.64.192`, `45.13.237.213`, `37.221.93.141`.
- `dns.bezmezhau.com`: **DoH недоступен**, а DoT по IP `91.108.243.78` отвечает (663 мс) — расхождение
  транспортов, у нас пресет уже переведён на этот IP.
- `dns.geohide.ru:8443`: мёртв и по DoH, и по DoT — апрельский адрес из дайджеста темы.
- `dns.wlrus.cfd`: TLS проходит, но Google отдаёт капчу → наши «валидные» IP здесь недостаточны.

## 4. Безопасность и риски инструмента

- EXE **без цифровой подписи** → SmartScreen предупреждает; проверить происхождение нельзя,
  кроме репутации поста.
- Локальный HTTP без аутентификации: любой процесс (и потенциально веб-страница через
  cross-site POST на `127.0.0.1:8765`) может вызвать `/api/apply` (запись политики, UAC),
  `/api/quit`, `/api/remove`. На практике мешает редко, но это вектор.
- Права администратора нужны только на «Применить»; изменение ограничено Chrome.
- Телеметрии в конфиге/UI нет; весь наблюдаемый трафик — DoH-серверы и Google.
  Остаточный риск: логика лежит в сжатом PYZ внутри EXE, статически её полностью не проверить
  без декомпиляции байткода Python 3.14 (инструментов под 3.14 нет).

## 5. Сверка с нашим приложением

| Возможность | DoH Manager | DnsHostsGenerator |
|---|---|---|
| Платформа | только Windows + Chrome | Android (+ Windows desktop) |
| Транспорт проверки | **DoH** (GET `?dns=`) | **DoT/853 + UDP/TCP:53** (DoH нет) |
| Проверка «IP реально обслуживает домен» | TLS + **headless Chrome** (капча, `sorry`, заглушка, экран входа) | TLS-хендшейк + сертификат (наш `IpValidator`) |
| Целевые домены | 4 гугловых | группы: 30 групп / 348 доменов (OpenAI, Gemini, Claude, Grok, Spotify, GitHub…) |
| Сравнение с DNS провайдера | да («как у провайдера» / «другой узел») | да (`#forwarded` — только если все адреса совпали) |
| Замер скорости | да (DoH/TLS, мс) | нет (только порядок и время запроса в логе) |
| Результат работы | политика Chrome (`HKLM`, UAC) | hosts-файл + импорт в NextDNS (API) |
| Поддомены | не применимо (DNS целиком) | только перечисленные имена |
| Без прав администратора | только проверка | да, всё |

Пересечение по смыслу большое: оба инструмента отвечают на вопрос «какой DNS сейчас реально
пускает в сервис». Разница в том, что DoH Manager проверяет **браузером** и применяет
**политику браузера**, а мы проверяем **TLS** и отдаём **hosts/DNS-профиль**.

## 6. Что из этого стоит взять в наше приложение

**P1 — данные (сразу)**
1. Добавить пресет `dns.dagami.ru` — проверено: UDP/DoT/DoH, 82 мс, прокси `45.147.31.32`
   валиден для chatgpt/gemini.
2. `dns.wlrus.cfd` — понизить статус: TLS проходит, но Google отдаёт `/sorry` (капча).
   Либо выключить, либо пометить «выдаёт капчу Google» в `disabledReason`.

**P2 — качество вердикта**
3. **Probe на капчу/заглушку**: HTTP GET целевой страницы через проверяемый IP и детект
   `302 → google.com/sorry` (и текста «недоступно в вашей стране»). Это ровно то, чего не хватает
   нашему TLS-валидатору: `wlrus` у нас «работает», а фактически не пускает.
4. Показывать в UI причину отказа по категориям (как у них: «нет A-записей», «TLS не прошёл»,
   «капча», «заглушка») — у нас сейчас `#unresolvedDomain` без деталей.

**P3 — транспорт и паритет**
5. **DoH-клиент** (RFC 8484, GET/POST `application/dns-message`): без него недоступны
   `dns.dagami.ru` (DoH-ветка), `dns.dns-ai.ru`, `dns.adguard-dns.com`.
6. **Настольная фича**: применить DoH-политику Chrome (`HKLM\SOFTWARE\Policies\Google\Chrome`)
   и кнопка «выключить». Только desktop, с явным UAC и предупреждением; локального HTTP-сервера,
   как у них, делать не нужно — у нас нативный UI, вектор `/api/apply` не воспроизводится.

**Не копировать**
7. Их «сервер на 127.0.0.1 без авторизации» и «EXE без подписи» — нам это не нужно:
   у нас нативный UI и обычная подпись-сборка.

## 7. Итог

Инструмент делает свою узкую задачу честно: реальные статусы (подтверждено независимыми
измерениями — `eu.geohide` работает, `:8443` и DoH bezmezhau мертвы, wlrus ловит капчу),
быстрый прогон, аккуратная запись только в политику Chrome. Но он про **один браузер на Windows
и гугловые домены**, тогда как наше приложение — про **списки доменов, Android и hosts/NextDNS**.

Практическая польза для нас — два факта и два улучшения: новый рабочий резолвер `dns.dagami.ru`,
подтверждение, что `wlrus` уже «капчится», и приоритет на детект капчи/заглушки + DoH-транспорт.
