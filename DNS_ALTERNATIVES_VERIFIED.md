# Альтернативы NextDNS: фактические проверки

## Зафиксированный итог после проверки на телефоне

- По подтверждению пользователя, стабильный рабочий сценарий сейчас — ПК с файлом hosts; GPT API на ПК работает.
- Android не считаем стабильным поддержанным сценарием. В браузере ChatGPT заработал через personalDNSfilter, но приложение ChatGPT продолжает возвращать ошибку региона. Загрузка страницы не подтверждает полноценную работу приложения.
- personalDNSfilter нарушал локальную связь TaskBridge; после добавления TaskBridge в исключения пользователь сообщил о восстановлении связи. Длительная стабильность этой схемы не подтверждена.
- NextDNS исключён: импорт работает через внешний VPN, но персональный Private DNS без него недоступен.
- Cloudflare Gateway заблокирован на этапе активации: Free требует платёжный способ и согласие на возможные списания. Пользователь считает это блокером; персональные Override не проверены.
- Control D не подходит как бесплатное решение из-за платного доступа к необходимому функционалу.
- Решение: фиксируем рабочий сценарий на ПК. Новые интеграции и обходные пути пока не добавляем.

Ниже сохранены результаты первоначального этапа исследования на ПК; они не заменяют этот итог.

## Границы первоначальной проверки

NextDNS исключён из рабочего сценария: пользователь подтвердил, что импорт проходит через VPN, но после отключения VPN Private DNS не работает.

Новые сетевые проверки выполнены с ПК в текущем окружении, не с телефона. Отсутствие VPN на всех уровнях маршрутизации отдельно не подтверждалось. Успешный DNS-запрос не доказывает доступность целевого сайта или работоспособность пользовательских правил облачного сервиса.

Продуктовый код и настройки телефона не менялись. Тестовые Java-процессы остановлены; локальный тест слушал только 127.0.0.1:15353. Все файлы эксперимента находятся в `build/dns-alternatives-probe/`.

## 1. personalDNSfilter — подтверждена локальная подмена DNS

Источник: https://github.com/IngoZenz/personaldnsfilter

Git commit исходников: `38951ab6b6edae40fa80cfae630ae4aaec89fcbd`. Latest release по GitHub API: `1.50.61.5`.

Скачаны 45 Java-файлов не-Android части и два штатных конфигурационных файла. Скомпилированы javac 17: успешно, одно предупреждение о deprecated `new Boolean(...)`, плюс unchecked operations.

Тестовый launcher запускает оригинальные `DNSFilterManager` и `DNSFilterProxy`, минуя сетевой bootstrap standalone-main. Upstream-сервер не инициализируется: эти ответы формируются локально. Первая попытка штатного standalone-main не дошла до открытия порта, ожидая bootstrap; её результаты не считаются проверкой правил.

### Базовые тесты

Реальные UDP DNS-запросы к локальному процессу:

| Имя | Ожидалось | Получено |
|---|---|---|
| probe.example | 192.0.2.42 | 192.0.2.42 |
| child.wild.example | 192.0.2.43 | 192.0.2.43 |
| PROBE.EXAMPLE | 192.0.2.42 | 192.0.2.42 |

3/3 успешно. Проверены также число ответов и transaction ID. IP взяты из документационного диапазона TEST-NET, это не реальные адреса сервисов.

### Защита от обхода через IPv6 и HTTPS/SVCB

Одной IPv4-подмены недостаточно: по исходникам сопоставления IPv4 и IPv6 независимы. Для теста использованы правила:

```text
>probe.example 192.0.2.42
probe.example
>*.wild.example 192.0.2.43
*.wild.example
```

Строка `>имя IP` задаёт подмену. Следующая строка блокирует остальные ответы для этого имени; пользовательская IP-подмена имеет приоритет.

Для точного имени и wildcard проверены четыре типа запросов:

| Тип | Фактический результат |
|---|---|
| A (1) | Заданный IPv4, RCODE=0, один ответ |
| AAAA (28) | ::, RCODE=0, один ответ |
| SVCB (64) | REFUSED (RCODE=5), ноль ответов |
| HTTPS (65) | REFUSED (RCODE=5), ноль ответов |

8/8 успешно. Это проверка DNS-политики; совместимость отказа HTTPS/SVCB с конкретными Android-приложениями требует проверки на телефоне. Такая блокировка затронет и другие типы записей этих имён.

### Ограничения

- Без root обычный Android-режим использует локальный VpnService и занимает VPN-слот; это не зарубежный VPN-туннель.
- Реальная работа Android-службы, импорт файла через UI, Private DNS/браузерный DoH, автозапуск и энергосбережение не проверены.
- Работа целевых сайтов после подмены не проверена.
- Wildcard нельзя автоматически распространять на поддомены: подтверждённый для одного имени IP не обязательно обслуживает все остальные.

Исходные форматы: [additionalHosts.txt](https://raw.githubusercontent.com/IngoZenz/personaldnsfilter/38951ab6b6edae40fa80cfae630ae4aaec89fcbd/app/src/main/assets/additionalHosts.txt), [dnsfilter.conf](https://raw.githubusercontent.com/IngoZenz/personaldnsfilter/38951ab6b6edae40fa80cfae630ae4aaec89fcbd/app/src/main/assets/dnsfilter.conf).

## 2. Cloudflare Gateway — подтверждён DNS-транспорт, не пользовательский Override

Реальный запрос `example.com A` к `dns.cloudflare-gateway.com:853`:

- Python TLS: ошибка `unable to get local issuer certificate`.
- Повторная независимая проверка Java 17: сертификат и hostname проверены штатным trust store, без отключения валидации; TLS успешен.
- Получен DNS-ответ: RCODE=0, два ответа.

Следовательно, этот общий DoT endpoint доступен из текущего окружения; Python-ошибка не доказывает сетевую блокировку.

**Не подтверждено:** регистрация бесплатного аккаунта, создание Override на Free, индивидуальный DoT endpoint локации, применение заданного IP, работа с телефона. Для этого нужен аккаунт и тестовая локация; общий endpoint этих вопросов не закрывает.

Документация подтверждает индивидуальные DoT-hostnames: https://developers.cloudflare.com/cloudflare-one/traffic-controls/resolver-endpoints/dns-over-tls/

## 3. Другие DoT-серверы: проверка транспорта

TLS с проверкой сертификата + реальный `example.com A`:

| Сервер | Результат |
|---|---|
| dns.nextdns.io:853 | TLS handshake timeout (~6 с) |
| dns.adguard-dns.com:853 | TLS успешен, RCODE=0, два ответа |
| eu.geohide.ru:853 | TLS успешен, RCODE=0, два ответа |
| dns.zapret.moe:853 | TLS успешен, RCODE=0, два ответа |

Публичные eu.geohide/zapret не дают персонального импорта hosts: ими управляет провайдер. Private AdGuard DNS остаётся кандидатом: доступность публичного endpoint не подтверждает доступность API, индивидуального endpoint или лимиты бесплатного аккаунта.

## Приоритет

1. personalDNSfilter: следующий минимальный тест — на телефоне точная подмена одного рабочего домена, проверка A/AAAA и самого сайта без внешнего VPN. После этого имеет смысл делать специальный экспорт/интеграцию.
2. Cloudflare Gateway: проверить Override и индивидуальную локацию на Free-аккаунте, затем повторить DNS-запрос с телефона.
3. Private AdGuard DNS: резервный кандидат, пока без проверки персональных правил.

Полностью подтверждённой замены на телефоне на этом этапе нет. В отличие от одной документации, у personalDNSfilter проверено ядро подмен, у Cloudflare — реальный DoT-запрос.
