# Пост 4PDA → чистый текст

## Что делать в первую очередь

```bash
python .pi/skills/4pda-post/scripts/extract_4pda_post.py <pid-или-ссылка> [--links] [--all] [--json]
```

- `<pid>` — число из `p=143495976`; можно передать ссылку целиком.
- `--all` — все посты загруженной страницы (20 постов), `--links` — внешние ссылки поста.
- Скрипт печатает UTF-8 в stdout; на Windows консоль иначе падает на `✓`/эмодзи.
  Для файла: `... > post.txt`, для анализа в коде: `--json`.

Проверка успеха: в выводе есть `## Пост #N (pid=...) — автор, дата` и непустой текст.

## Устройство страниц 4PDA (проверено 23.10.2026)

| Что | Факт |
|---|---|
| Кодировка | **cp1251**, не UTF-8. Чтение как UTF-8 даёт мусор; определять по `meta charset`. |
| UA | Нужен браузерный User-Agent (`Mozilla/5.0 ... Chrome/...`), иначе возможен отказ. |
| Ссылка на пост | `?act=findpost&pid=PID` редиректит на нужную страницу: `showtopic=ID&st=N#entryPID`. |
| Пагинация | По 20 постов: `showtopic=ID&st=0,20,40,...`. `--all` даёт только текущую страницу. |
| Контейнер поста | `<div data-post="PID">`, внутри `<a name="entryPID">` (это `name`, не `id`). |
| Тело поста | `<div class="post_body emoticons" id="post-main-PID">`. |
| Автор | `<span class="post_nick"> ... <a>ник</a>`; значок `ᵥ` — служебный, удалять. |
| Дата / номер | `span.post_date` (`21.05.26, 18:27`), номер — `#642` в `link_to_post(PID)`. |
| Правка | «Сообщение отредактировал <ник> — <дата>», причина правки рядом. |
| Спойлер / цитата | `<div class="spoil...">` / `<div class="quote...">` — текст внутри теряется при наивном strip, поэтому скрипт ставит маркеры `[СПОЙЛЕР]` / `[ЦИТАТА]`. |
| Вложения | `act=attach&code=...`; скачивание — отдельный шаг, часто требует логина. |

## Грабли

- **Не** разбирать пост регуляркой `id="entryPID"` — такого `id` нет, будет «пост не найден».
- Встроенный веб-экстрактор (`get-single-web-page-content`) обрезает страницу на 10 000 символов:
  длинный пост обрывается на середине. Для полного текста — только локальный парсинг.
- Границы поста: следующий `<div data-post=`, иначе в текст попадёт подпись, репутация и меню следующего.
- `st=` в ссылке не значит «страница N» — это смещение в постах; доверять редиректу.
- Не тянуть тему целиком без нужды: 80+ страниц × 20 постов. Сначала `--all` на странице поста,
  потом следующие `st`, если нужен контекст обсуждения.
- Тема может быть про иную тему, чем кажется по названию: сверять заголовок (`<title>`) и номер поста.

## Рабочий сценарий анализа

1. Извлечь пост скриптом (`--links`), сохранить в файл.
2. Отделить: заявление автора / факты / ссылки / обещания.
3. Проверить внешние ссылки (репозитории, сайты, статьи) — отдельно, не выдавать за проверенное.
4. Если пост про наш проект/стек — сопоставить с кодом и живыми измерениями, а не с текстом.
