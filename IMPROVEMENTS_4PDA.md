# DnsHostsGenerator — анализ доработок по итогам темы 4PDA «DNS CLUB»

Основание: полный разбор темы showtopic=1117490 (71 страница, 1421 пост, 293 вложения,
данные в TaskBridge: `.local/4pda/topic/1117490/`, отчёт `1117490-ANALYSIS.md`) и инвентаризация
кода приложения. Всё, что ниже, привязано либо к факту из темы, либо к конкретному месту в коде.

## 1. Что приложение уже закрывает (проверено по коду)

| Возможность | Где в коде | Комментарий |
|---|---|---|
| Группы доменов, Room KMP | `data/db/*`, seed 29 групп / 348 доменов | группы совпадают по составу с темой (OpenAI, Gemini, Copilot/Xbox, Claude, Grok, ElevenLabs, DeepL, JetBrains…) |
| Генерация hosts через DoT + fallback UDP/TCP | `generator/HostsGenerator.kt`, `resolver/*` | параллельно (Semaphore), `#forwarded`-детект перехвата DNS |
| Сравнение нескольких DNS | `HostsGeneratorViewModel.generateHosts()` | то, что в теме делают «паками» под каждого провайдера |
| 8 DNS-пресетов | `data/BuiltInDnsPresets.kt` | comss.one, xbox-dns, geohide, malw.link, shecan, astracat — ровно провайдеры из темы |
| Импорт в NextDNS Rewrites (Android) | `nextdns/*` | создание профиля, повторы 429, прогресс |
| Парсер ввода | `nextdns/HostsParser.kt` | hosts + plain-список; 12.10.2026 добавлены AdGuard/zapret `\|\|d^$dnsrewrite=ip` и dnsmasq `server=/d/ip` (тесты: jvmTest 15/15) |
| Сохранение результата | `platform/FileSaver.kt` (expect/actual) | один файл, один формат |
| Правка системного hosts | `platform/SystemHostsUpdater*.kt` | **незакоммиченный WIP — не трогать** |

Ядро приложения совпадает с главным инструментом сообщества — `hostparser`
(github.com/pengvench/hostparser: `core_domains.txt` → резолв через несколько DNS → вывод).
Разница в том, что hostparser отдаёт результат **сразу в четырёх форматах**, а приложение — в одном.

## 2. Доработки по убыванию ценности

### D1. Импорт списков в группы — сейчас это баг, а не фича. Приоритет: максимальный

**Факт (исполнено, не на глаз).** `HostsGeneratorViewModel.toDomainLineOrNull()` принимает
только «голые домены». Прогон реальных строк из файлов темы:

```
chatgpt.com                                  -> chatgpt.com            (ок)
103.137.248.179 chatgpt.com                  -> null                   (hosts-строка молча теряется)
||chatgpt.com^$dnsrewrite=103.137.248.179    -> ||chatgpt.com^$dnsrewrite=103.137.248.179  (!)
server=/chatgpt.com/83.220.169.155           -> null                   (dnsmasq теряется)
```

То есть: вставка `aihosts.txt` в группу теряет **все** строки; вставка `adguard.txt` не теряет
ничего, а **записывает в БД мусор вида `||chatgpt.com^$dnsrewrite=...`** как «домен»
(проверка `'.' in it && ' ' !in it` его пропускает). Мусор затем попадает в
`toEnabledDomainText()` и в генерацию hosts.

**Изменение.** В `addDomains()` заменить `text.toDomainLines()` на `HostsParser.parseInput(text)`
(он уже умеет все четыре диалекта и показывает issues/conflicts). В статусе показывать
«добавлено N, проблем M, конфликтов K». Заодно — дедуп против уже существующих доменов группы.

**Объём/риск:** ~30–40 строк в ViewModel + тесты на `parseInput` уже есть. Риск низкий;
поведение для «чистых списков» не меняется.

### A1. Экспорт результата в 4 форматах. Приоритет: высокий

**Факт из темы.** Паки `dnscomssone-*.zip` / `xboxdnsru-*.zip` содержат один и тот же список
в четырёх видах — так сообщество делится результатом:

```
aihosts.txt    103.137.248.179 chatgpt.com                  # hosts (есть в приложении)
aihosts.conf   server=/chatgpt.com/83.220.169.155           # dnsmasq (нет)
adguard.txt    ||chatgpt.com^$dnsrewrite=103.137.248.179    # AdGuard (нет)
nextdns.txt    103.137.248.179 chatgpt.com                  # для импорта в NextDNS (нет как файла; есть API-импорт)
```

**Изменение.** `commonMain/export/HostsExporters.kt`: чистые функции
`toHostsText/toDnsmasqConf/toAdguardRules/toNextDnsList` над `GenerationResult`
(из `HostLine.Resolved`); в блоке результата — выбор формата + прежнее `saveFile()`.
Имена файлов — по образцу `outputFileName` (`host_out_dns.comss.one.txt` → `.conf`, `.adguard`).

**Объём/риск:** ~80–100 строк + golden-тесты на строках из реальных паков. Риск низкий:
чистая функция, UI-обвязка минимальная.

### B1. ZIP-импорт и экспорт. Приоритет: средний

**Факт из темы.** 15 из 49 скачанных файлов — zip; списки распространяются архивами
(внутри 2–4 файла, встречаются и вложенные каталоги инструментов). `dnsnet3.json.zip`
вообще не zip, а JSON — расширение врать не должно.

**Изменение.** `expect/actual ZipTextArchive`: `list(entry) -> List<String>` и
`pack(files: Map<String, String>)`. Таргеты только `jvm()` + `androidTarget`, поэтому
`java.util.zip` доступен на обеих платформах; чтобы не дублировать код — общий source set
(`jvmCommon`) либо два одинаковых actual-файла (~40 строк каждый). Выбор файла:
SAF на Android, JFileChooser на desktop. Импорт: распаковать, выбрать текстовый файл,
скормить `HostsParser.parseInput`. Экспорт: собрать 3–4 формата из A1 в один архив.

**Объём/риск:** средний (платформенная обвязка). Риск средний: работа с ФС на Android;
контент по байтам, не по расширению.

### C1. Обогащение seed-доменов — только после ручной проверки. Приоритет: средний

**Факт.** В текстовых файлах темы 359 уникальных доменов; 150 нет в seed. Из них:
16 — ИИ-сервисы (`oaistatic.com`, `oaiusercontent.com`, `claude.com`, `mobile.openai.com`,
`grok.x.com`, `cdn/beta/auth.elevenlabs.io`…), 15 — реклама/трекеры (`adfox.yandex.ru`,
`an.yandex.ru`, `appmetrica…`), остальные — прочие сервисы. В списках темы встречаются
**опечатки** (`ita-free.app.deepl.cpm`) — бездумный импорт загадит базу.

**Изменение.** Добавить проверенные вручную ИИ-домены в `DefaultDomainList.kt` и
перегенерировать `seed_data.sql`. Нюанс: SQL помечен «Auto-generated from DefaultDomainList.kt»,
но генератора в репозитории нет (grep находит только `SeedCallback.kt`, который его читает) —
надо выяснить, чем он создавался, иначе расхождение source-of-truth.

**Объём/риск:** малый по коду, но требует ручной сверки каждого домена; без верификации не делать.

### F1. Golden-фикстуры из живых файлов. Приоритет: низкий, дёшево

**Факт.** У меня уже есть 23 txt из темы; фрагменты строк уже вшиты в `HostsParserTest`.
Полные файлы (rules.txt: 169 rewrites/28 issues; adguard.txt: 55/0; Hosts(ComssDNS).txt: 195/0)
— готовые эталоны для регрессии диалектов.

**Изменение.** Положить 3–4 файла в `commonTest/resources`, добавить тесты с точными счётчиками.
Данные из форума — с осторожностью (лицензии/авторство: в файлах указан автор — упомянуть источник в комментарии).

### E1. Загрузка списка по URL. Приоритет: низкий

**Факт.** Шапка темы ссылается на внешние списки (dnscrypt public-servers, GitHub-проекты).
4PDA-вложения так не взять: анти-бот отдаёт их только браузерной навигацией (проверено:
HTTP-запрос → 403; событие download приходит через ~10 с; text/plain вообще показывается в окне).
Это ограничение надо честно зафиксировать в UI.

**Изменение.** Ktor-загрузка текста в поле импорта (GitHub raw, свои URL), лимит размера.
Для 4PDA — не пытаться.

## 3. Что НЕ делать (и почему)

- **WARP/wireguard-конфиги** (`AI-Fix-Configs.zip`, `gemini.zip`) — другой класс решений, не hosts.
- **SNI-прокси** (`dns-sni-proxy-hosts-generator`) — другой целевой артефакт; если когда-нибудь
  понадобится экспорт «hosts для SNI-прокси», это отдельная кнопка в A1, не ядро.
- **Анти-рекламные DNS** (dismail, libredns, dnsforge, blahdns) — вне назначения приложения
  (разблокировка ИИ, не блокировка рекламы); в пресеты не добавлять.
- **Обход анти-бота 4PDA внутри приложения** — нет и не нужно; списки берутся руками.
- **`SystemHostsUpdater` (WIP)** — незакоммиченная работа, в анализ изменений не включать,
  интеграция с экспортом (A1) — после того, как она устоится.

## 4. Порядок работ

1. **D1** — баг импорта (мусор в БД сегодня).
2. **A1** — экспорт в 4 форматах (главное расхождение с практикой сообщества).
3. **F1** — golden-фикстуры (дёшево, страхует 1–2).
4. **B1** — zip-импорт/экспорт.
5. **C1** — seed после ручной сверки.
6. **E1** — по желанию.

Суммарно D1+A1+F1 — это ~200 строк кода и тестов, без новых зависимостей и без платформенных
изменений; всё в commonMain, кроме двух копий zip-кода в B1.
